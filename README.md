# Figzen

Figzen is a minimal, local-first Figma plugin that converts a selected Figma Frame into an editable Godot 4 `.tscn` scene.

## What it exports

Supported mappings:

- Frame → `Control`
- Rectangle → `ColorRect`
- Text → `Label`
- Component / Instance → `Control`, recursively preserving supported children
- Any other Figma node → `Control` with a warning

Preserved in Phase 1:

- Node names
- Recursive hierarchy
- Position and size
- Visibility
- Solid fill colors
- Text content
- Text font size

The plugin creates the `.tscn` text in the Figma plugin runtime and packages it into a ZIP entirely in the plugin UI. There is no backend, database, account system, cloud storage, telemetry, analytics, AI service, or network call.

## Build

Requirements:

- Node.js 18+
- TypeScript available through `npm install`
- `zip` command available on the build machine

Run:

```bash
npm install
npm run typecheck
npm run test
npm run build
```

The build outputs:

- `dist/manifest.json`
- `dist/code.js`
- `dist/ui.html`
- `figzen-plugin.zip`

## Load into Figma

1. In Figma Desktop, open **Plugins → Development → Import plugin from manifest…**.
2. Select this project's `manifest.json`.
3. Run Figzen from **Plugins → Development**.
4. Select a Frame and click **Export selected Frame**.
5. Extract the downloaded ZIP into a Godot 4 project.
6. Open the generated `.tscn` in Godot.

## Test example

The repository includes `examples/sample.tscn`. It demonstrates a `Control` root, a colored `ColorRect`, a `Label`, and a nested `Control` containing another `ColorRect` and `Label`.

A matching Figma test frame can be made with:

```text
Root (Frame)
├── Background (Rectangle)
├── Title (Text)
└── Card (Component or Frame)
    ├── CardFill (Rectangle)
    └── Body (Text)
```

Exporting it should produce the same basic hierarchy and editable Godot node types.

## Warnings

Warnings are shown in the plugin UI after export. Unsupported nodes are not silently discarded: they become `Control` nodes so their hierarchy and geometry can remain present while the unsupported visual behavior is called out.

## Known limitations

Phase 1 does not export gradients, image fills, strokes, corner radii, opacity, effects, typography family/weight/style, text alignment/wrapping, auto-layout constraints, rotation, transforms, component variants, masks, boolean geometry, vectors, groups as special Godot node types, prototype interactions, or Figma-specific effects.

Geometry is based on Figma absolute bounding boxes relative to the immediate parent bounding box. This preserves the visible rectangular placement but is not a full reproduction of Figma's layout engine.

Figma node names containing path separators may require manual renaming in Godot if they conflict with Godot node-path syntax.

Large frames can create large UI messages because the generated scene is sent from the plugin code to the UI for ZIP packaging.

The project can be typechecked and built outside Figma, but actual Figma-runtime behavior and Godot import behavior should still be smoke-tested in Figma Desktop and Godot 4 respectively.

## Future improvements

The cleanest next additions are:

1. Auto-layout → Godot containers and anchors.
2. Typography mapping including font family, weight, line height, alignment, and wrapping.
3. Corner radius and border/stroke mapping.
4. Rotation and full transform mapping.
5. Images and SVG/vector export into the ZIP.
6. Component/variant metadata and reusable Godot scenes/resources.
7. Export settings for root node type, pixel snapping, and naming policy.
8. A validation pass that can flag geometry/layout cases likely to diverge before export.
